# プロダクト要求定義書

## プロダクトビジョンと目的

`claude-code-toolkit` は、複数のリポジトリで共有する Claude Code の設定(スキル・フック・権限設定・開発コンテナ設定など)を1箇所で管理し、Claude Code の公式プラグイン機構(マーケットプレイス)を通じて配布するためのツールキットです。

特定のプロダクトドメインに依存しない汎用的な設定として作られており、このリポジトリ自体が Claude Code のプラグインマーケットプレイスを兼ねています(`.claude-plugin/marketplace.json`)。

## ターゲットユーザーと課題・ニーズ

- **想定ユーザー**: 複数のプロジェクト・リポジトリで Claude Code を使う開発者(このリポジトリの場合は個人開発者)
- **課題**: プロジェクトごとに `permissions`(権限設定)・フック・ステアリング運用のルールをコピー&ペーストで持ち回ると、リポジトリ間で設定が乖離し、改善が個別プロジェクトにしか反映されない
- **ニーズ**: 権限方針・フック・スキル(`commit`/`steering-new` など)を1箇所で更新し、複数リポジトリへ簡単に反映したい

## 主要な機能一覧

- **スキル配布**(`plugins/core/skills/`): `commit`(コミット規約に従ったコミット作成)、`steering-new`(ステアリングドキュメントの作成、ワークフロー切り替え対応)
- **フック配布**(`plugins/core/hooks/`): 禁止コマンドの遮断、削除・変更された識別子のドキュメント陳腐化チェック、テスト実行の強制
- **権限設定テンプレート**(`.claude/settings.json`): `deny`/`ask` による禁止・承認事項の宣言
- **開発コンテナ設定**(`.devcontainer/`): Claude Code CLI を含むコンテナ定義、設定の永続化
- **ステアリング運用**(`.steering/`): 開発作業ごとの要求・設計・タスクの記録方式

## 機能要件

- Claude Code の公式プラグインマーケットプレイス機構(`claude plugin marketplace add` / `claude plugin install`)経由で `core` プラグインを配布できること
- マーケットプレイス機構の対象外の設定(`permissions`/`sandbox`・`claude.md`・`.devcontainer/devcontainer.json`)は、利用側リポジトリがこのリポジトリの実体を参照してコピーできる形で提供すること
- `steering-new` スキルは、ワークフロー(`--workflow=<id>`)を切り替えることで、承認ゲートの有無や作成するドキュメントを変えられること(`plugins/core/skills/steering-new/workflows/*.yaml`)

## 非機能要件

- **開発中であり後方互換性を保証しない**(`0.x.x` のベータ版。詳細は `claude.md` の「バージョニングと後方互換性ポリシー」)
- **開発コンテナ内での利用を前提とする**。権限方針(既定で承認なし)は、コンテナ外部のファイルシステムに到達できないことを前提に成り立っている
- テストコマンドはリポジトリごとに異なるため本体には含めない。`.claude/test-command` があれば `stop-run-tests.sh` フックが実行する
