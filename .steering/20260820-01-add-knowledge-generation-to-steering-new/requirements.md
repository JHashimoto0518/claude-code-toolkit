# steering-newスキルへのknowledge生成の追加

## 要点

**steering-new の各ワークフローの末尾に、そのステアリングを通じてClaudeが学んだこと(特にユーザーの意図とClaudeの当初の出力との差分から読み取れる情報。対人コミュニケーションの文章では読み手の感情・理解のしやすさへの配慮も含む)を `knowledge.md` として書き出す新しい手順種別 `kind: knowledge` を追加し、4つの既存ワークフロー(`standard` / `minor-fix` / `exploratory` / `investigation`)すべての最後に組み込む。** 今回捨てるのは「ステアリングを通じて得られた学びが `requirements.md` / `design.md` / 会話履歴・diff の中に暗黙的にしか残らず、以降のステアリングがそれを再利用するには生の記録を読み返して再解釈するしかない」という現状の方式であり、学びを明示的に蒸留した文書として残す方式に置き換える。

## 背景

steering-new スキルは現状、`overview.md` / `requirements.md` / `design.md` / `tasklist.md` を作成し、`kind: requirements` の背景セクションでは過去のステアリングディレクトリへの相対リンクによって経緯を示せる(`plugins/core/skills/steering-new/SKILL.md` 参照)。しかし、これらのドキュメントは「何を決めたか」「何を実装したか」を記録するものであり、「その過程でClaudeが何を学んだか」(特にユーザーの意図とClaudeの当初の理解・出力とのズレ)を蒸留した記録は残らない。

別リポジトリでの実例として、あるステアリング完了後にユーザーが次のように依頼したことがある。

例1:

> あなたが作成したCSVを読み込んだものをたたき台にExcelブックを作成しました。xxx.xlsxを読んで、あなたのCSVとの差異、特に私の意図を読み取ってください。それをこのステアリングのknowledge.mdとして作成してください。目的はあなたがこのステアリングで学んだことを以降のステアリングにつなげることです。

例2:

> 私が校正したチャットの文章をステアリングに格納しました。それを読んで、あなたのCSVとの差異、特に私の意図、文体、ニュアンスを読み取ってください。それをこのステアリングのknowledge.mdとして作成してください。

例1はClaudeの生成物(CSV)をユーザーが**リポジトリ外のファイル(xlsx)として**手を加えて仕上げたもの、例2はユーザーが**ステアリングディレクトリ内に格納した**校正済みの文章であり、比較対象の置き場所は異なるが、いずれも「Claudeの元の出力とユーザーが手を加えた結果を読み比べ、そこに表れた意図をClaudeが言語化して記録する」という構造は共通している。

一方で、例1と例2では学ぶべき内容の性質が異なる。例1は技術的な成果物(データ)の意図の読み取りだが、例2の意図は、技術文書ではなく**対人コミュニケーションの文章(チャットメッセージなど)をClaudeが作成する場合、内容の正しさだけでなく、読み手の感情や理解のしやすさに配慮してほしい**という学びを指す。つまり `knowledge.md` が捉えるべき学びは、成果物の性質(技術的なデータ・コードか、対人コミュニケーションの文章か)によって観点が変わりうる。この運用を steering-new スキルの標準的な手順として一般化し、成果物比較に限らず、requirements/design/実装の各段階でユーザーから受けた訂正・フィードバックからも学びを抽出できるようにする。

## 変更・追加する機能の説明

### 1. 新しい手順種別 `kind: knowledge`

ステアリングの過程(requirements/design の承認時のやり取り、実装への訂正、ユーザーが手を加えた成果物との差分など)を振り返り、`knowledge.md` に次を記載する。

- そのステアリングでClaudeが学んだこと(特にユーザーの意図とClaudeの当初の理解・出力とのズレ)。成果物が対人コミュニケーションの文章(チャットメッセージなど)である場合は、内容の正しさに加えて読み手の感情・理解のしやすさへの配慮の観点も含める
- 学びの根拠(何と何を比較して分かったか。会話中の訂正か、成果物との差分か。差分がある場合は比較対象の置き場所(リポジトリ外のファイルか、ステアリングディレクトリ内に格納されたファイルか)も含む)
- 以降のステアリングで踏まえるべき点

ユーザーがClaudeの出力を手直しした結果を提示した場合は、それを読み込みClaudeの元の出力との差分を比較して反映する。比較対象は例1のようにリポジトリ外のファイル(パスを指定して読む)の場合と、例2のようにステアリングディレクトリ内に格納されたファイルの場合の両方があり得るため、どちらの置き場所であっても対応できるようにする。差分の比較対象が提示されない場合も、requirements/design/implementation の各ステップで得られた訂正・フィードバックを基に記載する。

### 2. 全ワークフローへの組み込み

`standard` / `minor-fix` / `exploratory` / `investigation` の4つの既存ワークフロー定義(`plugins/core/skills/steering-new/workflows/*.yaml`)すべての末尾に `kind: knowledge` のステップを追加する。ワークフローの種類によって省略しない。

### 3. 過去の knowledge.md の参照

既存の `kind: requirements` は過去のステアリングディレクトリへの相対リンクで経緯を示せる運用になっている。これに加えて、新しいステアリング作成時に関連する過去の `knowledge.md` を参照できるようにし、「学びを以降のステアリングにつなげる」という目的を実際につなげる。参照の具体的な組み込み方(どの `kind` でどう案内するか)は design.md で決定する。

## 受け入れ条件

- [ ] `plugins/core/skills/steering-new/SKILL.md` に手順種別 `kind: knowledge` が定義されている
- [ ] `standard` / `minor-fix` / `exploratory` / `investigation` の4つのワークフロー定義すべてに `kind: knowledge` のステップが追加されている
- [ ] `knowledge.md` には、そのステアリングでClaudeが学んだこと(特にユーザーの意図とClaudeの当初の出力とのズレ。対人コミュニケーションの文章では読み手の感情・理解のしやすさへの配慮も含む)とその根拠が記載される
- [ ] ユーザーが提示したClaudeの出力の手直し結果(リポジトリ外のファイル・ステアリングディレクトリ内に格納されたファイルのいずれも)がある場合、それを読み込みClaudeの元の出力との差分を比較して反映する運用がSKILL.mdに明記されている
- [ ] 以降のステアリング作成時に過去の `knowledge.md` を参照する導線がある

## 制約事項

- `knowledge.md` の生成はすべてのワークフローで必須とし、条件分岐で省略しない
- 対象は steering-new スキルの挙動定義(`plugins/core/skills/steering-new/` 配下)に限る。他スキル(core:commit など)への適用は本ステアリングのスコープ外
