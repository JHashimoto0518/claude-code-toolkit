# CHANGELOG.mdの更新を自動化する

## 要点

**リポジトリルートに `CHANGELOG.md` を新設し、これまでの `.steering/` の履歴から初回分を一括生成した上で、以降は変更が発生するたびに手動操作なしで更新される仕組みを追加する。** 具体的にどのコンポーネント(`commit` スキル / `steering-new` スキル / フック)に自動更新を組み込むかは design.md で決める。今回捨てるのは「変更履歴がコミットログと `.steering/` ディレクトリに分散しており、対外的に(あるいは将来の自分が)俯瞰できる一覧が存在しない」状態である。

## 背景

このリポジトリは `.steering/[YYYYMMDD]-[NN]-[開発タイトル]/` を作業単位として、原則 1 ステアリング = 1 コミット(`change:`/`add:`/`fix:` などの prefix)で `main` に変更を積み重ねてきた(`git log --oneline` で 20260810 から現在まで 20件超のステアリングディレクトリに対応するコミットが確認できる)。しかし、この変更の一覧性は Git のコミットログにしか存在せず、`CHANGELOG.md` のような、変更内容を要約して読める形の記録がない。

`claude.md` の「バージョニングと後方互換性ポリシー」は「詳細な移行ガイドを `CHANGELOG.md` に記載する」ことに触れており、`README.md` の「永続的ドキュメントの更新対象の候補」にも `CHANGELOG.md`(`[Unreleased]` セクション)が挙げられている。つまり `CHANGELOG.md` の存在自体はこのリポジトリの既存ルールが前提としているが、実体がこれまで作られていなかった。

## 変更・追加する機能の説明

### 1. `CHANGELOG.md` の初回生成

既存の `.steering/` ディレクトリ・コミット履歴をもとに、これまでの変更を要約した `CHANGELOG.md` を作成する。1ステアリングディレクトリに対応しないコミット(例: フォローアップの `docs:` コミット)の扱い、エントリの粒度・フォーマットは design.md で決める。

### 2. 以降の更新の自動化

新しい変更(ステアリングを伴う開発、または軽微な修正)が行われるたびに、`CHANGELOG.md` への追記が手動操作なしで行われる仕組みを追加する。ユーザーは「ワークフローへの組み込み」を1案として想定しているが、`commit` スキルへの組み込みなど他の方式も比較検討し、design.md でどの方式を採るか決める。

## 受け入れ条件

- [ ] リポジトリルートに `CHANGELOG.md` が存在し、これまでの `.steering/` の履歴に対応する変更が時系列で分かる形にまとまっている
- [ ] 新しい変更(ステアリングを伴う開発、または軽微な修正)を1件行った際、`CHANGELOG.md` への追記が自動的に(ユーザーが `CHANGELOG.md` を手で編集することなく)行われる
- [ ] 自動更新の仕組みの決定理由(採用した方式・採らなかった方式とその理由)が design.md に記録されている

## 制約事項

- `CHANGELOG.md` のフォーマットは指定がないため、一般的な規約([Keep a Changelog](https://keepachangelog.com/) 等)を参考にしつつ、このリポジトリの運用(1ステアリング=1コミット、prefix によるコミット分類)に合わせた形にする
- 既存の `.steering/` ディレクトリ名・過去のコミットメッセージの変更は行わない(履歴の保全)
