# commit スキルに push まで含めるかどうかのオプションを追加

## 要点

`commit` スキルの手順5にある「**push はしない。** 明示的に指示された場合のみ行う」という固定の挙動を捨て、**`/core:commit` の引数で push の要否をその場で指定できるようにする**。

| 指定 | 挙動 |
|---|---|
| `/core:commit`(既定) | コミットのみ。push しない(現状と同じ) |
| push を指示するオプション付き | コミット後に続けて `git push` する |

push を指示するオプションと `--branch` は**排他**とする。新規ブランチの push は upstream の設定を伴い、その取り回しに見合う必要性がないため、組み合わせ自体を持たない。

判断の分担は次のとおり。

| 決めること | 担い手 |
|---|---|
| push するかどうか | ユーザー(スキル起動時の引数) |
| push してよいかの確認 | Claude Code の permission system(`Bash(git push*)` が `ask` のため確認ダイアログが出る) |
| force push の可否 | permission system(`deny` のため常に拒否。スキル側からは扱わない) |

**リポジトリ単位で push 方針を持たせる方式は採らない。** 中止した [`../20260812-03-enable-claude-git-push-abandoned/`](../20260812-03-enable-claude-git-push-abandoned/) はそれを狙ったものだったが、続く [`../20260813-01-review-permissions/`](../20260813-01-review-permissions/) で `Bash(git push*)` が `deny` から `ask` へ移り、リポジトリ単位の方針は `.claude/settings.json` の `permissions` だけで表現できるようになった。スキルが担うべきは「この 1 回のコミットで push まで行くか」という起動時の意思表示だけである。

## 背景

`commit` スキル(`plugins/core/skills/commit/SKILL.md`)の手順5は、コミット後の push を次のように固定している。

```markdown
- **push はしない。** 明示的に指示された場合のみ行う
```

この記述は、`plugins/core/assets/settings.permissions.json` で `Bash(git push*)` が一律 `deny` だった時期に書かれたもので、スキルと権限設定の 2 箇所が揃って「push しない」という単一の挙動を作っていた。

[`../20260813-01-review-permissions/`](../20260813-01-review-permissions/) で権限設定が見直され、`Bash(git push*)` は `permissions.ask` へ移った(`--force`/`-f` を伴うものだけが `deny` に残る)。権限側は「確認を挟めば push してよい」に変わったが、スキル側の文言は据え置かれているため、`/core:commit` で push まで行きたいときはユーザーがコミット後に別途指示するか、自分で `git push` を実行する必要がある。

`--branch` / `--here` と同様に、**この 1 回の実行でどこまで進めるかを引数で表明する**のがこのスキルの既存の作りであり、push もその軸に載せる。

## 変更・追加する機能の説明

### 1. push の要否を指定する引数の追加

`/core:commit` に、コミット後の push を指示するオプションを追加する。オプション名と、既定の挙動を明示するための対になるオプション(`--here` に相当するもの)を置くかどうかは design.md で決める。

- 既定(オプションなし)は現状どおり push しない
- `--here` およびコミットメッセージのタイトルと併用できる。オプションを取り除いた残りをタイトルとして扱う既存の解釈規則を崩さない

### 2. `--branch` との排他

push を指示するオプションと `--branch` / `--branch=<名前>` は**同時に指定できない**ものとする。新規作成したブランチにはリモート追跡ブランチがなく、upstream の設定を伴う push が必要になるが、その取り回しを引き受けるほどの必要性がないため、組み合わせ自体を禁じる。

- 両方が指定された場合はコミットもブランチ作成も行わず、排他である旨をユーザーに報告する
- ブランチを切ったうえで push したい場合は、`--branch` でコミットした後にユーザーが `git push -u` を実行する

### 3. 手順5の書き換え

「push はしない。明示的に指示された場合のみ行う」を、引数に応じた分岐へ置き換える。あわせて次を規定する。

- **push が拒否・失敗した場合の扱い。** コミット自体は既に成立しているため、コミットを取り消さずに失敗を報告する
- 対象は現在のブランチの upstream への push に限る(`--branch` と排他のため、upstream のないブランチを push する経路は生じない)

### 4. 報告内容への push 結果の追加

手順6の報告に、push を行った場合はその結果(成否、push 先のブランチ)を含める。

### 5. ドキュメントの更新

`SKILL.md` の frontmatter(`argument-hint`)・引数の表・使用例、および `README.md` のスキル一覧の説明のうち、push の扱いに触れる箇所を更新する。

## 受け入れ条件

- [ ] `/core:commit` を引数なしで実行した場合、コミットのみ行い push しない(現状と同じ)
- [ ] push を指示するオプションを付けて実行した場合、コミット後に現在のブランチの upstream へ `git push` が実行される
- [ ] push を指示するオプションと `--branch` を同時に指定した場合、コミットもブランチ作成も行われず、排他である旨が報告される
- [ ] push を指示するオプションとコミットメッセージのタイトルを併用した場合、オプションがタイトルに混入しない
- [ ] push が拒否・失敗した場合、コミットは取り消されず、push が失敗した旨が報告される
- [ ] 追加したオプションが `SKILL.md` の `argument-hint`・引数の表・使用例に反映されている

## 制約事項

- push の可否そのものは Claude Code の permission system が決める。スキルは push を試みるだけで、確認ダイアログの提示や拒否の判定を独自に実装しない(二重に確認を出さない)
- `--force` を伴う push はスキルの対象外とする。`plugins/core/assets/settings.permissions.json` の `deny` に残っており、解禁は本ステアリングの範囲ではない
- `plugins/core/assets/settings.permissions.json` は変更しない。`Bash(git push*)` を `ask` から `allow` 相当へ動かす(= 確認なしで push する)かどうかは利用側リポジトリの判断であり、スキル側で先回りしない
- このリポジトリに `docs/` は存在しないため、永続的ドキュメントの更新対象は `README.md` と `claude.md`(該当箇所がある場合)になる
