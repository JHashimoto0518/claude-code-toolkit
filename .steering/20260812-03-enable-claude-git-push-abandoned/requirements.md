# git pushをClaudeが実行可能にする

## 要点

現状 `git push` は `plugins/core/assets/settings.permissions.json` の `permissions.deny`(`Bash(git push*)`)で一律禁止されており、`commit` スキルにも「push はしない。明示的に指示された場合のみ行う」と明記されている(2箇所とも `/core:commit` 実行時の一貫した「pushしない」という単一の挙動を作っている)。**これを、リポジトリ単位で次の3モードから選べるようにする。**

| モード | 挙動 |
|---|---|
| 自動push | コミット後、承認なしで自動的にpushする |
| 承認後push | コミット後、承認を得てからpushする |
| push禁止(現状) | pushしない。明示的に指示された場合のみ行う |

今の方式で捨てるのは「pushは常に禁止で、必要なら都度ユーザーが手動実行する」という単一モードの決め打ちである。ただし後方互換性として、モードを指定しないリポジトリでは現状(push禁止)を維持する(制約事項参照)。モードの指定方法(設定ファイルの形式・置き場所)は design.md で決める。

## 背景

このリポジトリは複数リポジトリで共有する Claude Code の設定を配布するプラグインであり、`permissions`/`sandbox` 設定は `/core:setup` 経由で利用側リポジトリへコピーされる(コピー後の実体はコピー先の `.claude/settings.json` にあり、Claude 自身はそれを直接編集できない)。

現状、`git push` は共有設定・`commit` スキルの両方で一律禁止と決め打ちされている。これはリポジトリごとの運用(ブランチ保護、レビュー必須、CIでのみpushする方針など)を一切考慮しない単一の挙動であり、ユーザーから「リポジトリによってポリシーが異なりうるため、push方針を選べるようにしたい」という要望があった(`todo.md` の chore 項目、および同項目に付随する `.steering/20260812-01-.../` 以降のやり取りで確認された、他リポジトリ(`kids-mart-play` 等)へこのプラグインを導入する流れとも関連する)。

`.claude/test-command` は、共有スキル・フックの挙動をリポジトリごとに外部ファイルでカスタマイズする既存の前例であり(`[REMOVED]`)、今回も同様に「共有の仕組みは1つ、リポジトリごとの選択はオプトインの設定で切り替える」という設計方針を踏襲できないか、design.md で検討する。

## 変更・追加する機能の説明

### 1. push方針をリポジトリ単位で選択する仕組み

リポジトリごとに「自動push」「承認後push」「push禁止」のいずれかを選べるようにする。具体的な設定方法(`.claude/` 配下の新規ファイル、`.claude/settings.json` の permissions、その他)は design.md で決める。

### 2. `commit` スキルの挙動変更

`/core:commit` 実行時、上記で選択されたモードに従って push の要否・承認要否を判断する。現行の「push はしない。明示的に指示された場合のみ行う」という固定文言を、モードに応じた分岐へ置き換える。

### 3. `permissions.deny` の見直し

`Bash(git push*)` の一律denyのままでは「自動push」「承認後push」のどちらのモードも実現できない。deny の扱い方(モードに応じて外す、allow/ask へ切り替えるなど)を design.md で決める。

## 受け入れ条件

- [ ] リポジトリで「自動push」を選択した場合、`/core:commit` がコミット後に承認なしで push する
- [ ] リポジトリで「承認後push」を選択した場合、`/core:commit` がコミット後に承認を得てから push する
- [ ] リポジトリで「push禁止」を選択した場合(またはモード未指定の場合)、現状と同じく push しない
- [ ] モードを指定していない既存リポジトリの挙動が変わらない(デフォルトは push 禁止)
- [ ] モードの選択方法が `README.md` または `claude.md` から分かる

## 制約事項

- `.claude/settings.json` の `permissions` は多くの環境で Claude 自身の編集が拒否される想定のパスである。モード切り替えに `.claude/settings.json` の変更が伴う場合、Claude は内容を提示するに留め、適用はユーザーに依頼する(既存の `/core:setup` と同じ制約)
- 「push してよいか」という判断そのもの(ブランチ保護・レビュー必須などのポリシー適合性)はこのプラグインの責務ではない。あくまで3モードを切り替えられる仕組みを提供するに留め、各リポジトリの運用判断はユーザーに委ねる
- 既存リポジトリへの導入(`/core:setup` 済みの環境を含む)で、モード未指定時に意図せず push が有効化されないこと(後方互換性)
