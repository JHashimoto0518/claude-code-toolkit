# 別デバイスへの通知を実装する

## 要点

**`README.md` の「使い方」と「権限方針の要点」の間に、新規 `## 通知` セクションを追加する。** Remote Controlのペアリング手順・`/config`でのプッシュトグル有効化・注意点(プラン要件、通知タイミングの不確実性、Apple Watchの扱い)を簡潔に記載し、詳細は公式ドキュメントへのリンクに委ねる。コードやフックの実装は行わない。

| 論点 | 方式 | 決め手 |
|---|---|---|
| 挿入位置 | 「使い方」と「権限方針の要点」の間に独立した `## 通知` セクション | 独立した関心事であり、既存の他セクション(権限方針の要点・ステアリング運用)と同じ見出し粒度にすることで目次的に見つけやすくなる |
| 記載範囲 | ペアリング方法 → `/config` トグル → 注意点(プラン要件・タイミングの不確実性・Apple Watchの自動カバー)→ 公式ドキュメントへのリンク | requirements.md の受け入れ条件を満たす最小限。詳細を自前で説明せず公式ドキュメントに委ねるのは、既存の「権限方針の要点」(詳細は `claude.md` を参照)と同じパターン |
| 自前実装の要否 | 行わない | requirements.md の制約事項どおり、`Notification` フック + 外部プッシュサービス連携は今回のスコープ外 |

### 採らなかった選択肢

- **「使い方」内の既存の箇条書きに追記する** — 既存の箇条書きは1〜2文の短い注意点の羅列であり、ペアリング手順のような複数ステップを混ぜると可読性が落ちる。独立見出しの方が見つけやすい
- **`claude.md` に記載する** — `claude.md` はバージョニング・権限設定などプロジェクトの開発運用ポリシーを扱う場所で、想定読者はこのリポジトリの開発者自身。Remote Controlのセットアップは利用側リポジトリの担当者(人間)向けの手順であり、README に置く方が届きやすい

## 実装アプローチ

### README.md への追記

「使い方」セクションと「権限方針の要点」セクションの間に、次のセクションを挿入する。

```diff
 - `.claude/settings.local.json` はローカル環境固有の設定であり、共有対象に含めません(`.gitignore` 済み)

+## 通知
+
+Claude Codeがユーザーの入力待ち・権限確認待ちになった際、開発コンテナのターミナルベルだけでは開発PCの前にいないと気づけません。Claude Codeの **Remote Control** 機能を使うと、公式Claudeアプリ(iPhone/Android)へプッシュ通知を届けられます。
+
+1. `claude remote-control` を実行するか、セッション内で `/remote-control` を実行し、表示されるQRコードを公式Claudeアプリ(要インストール)でスキャンしてペアリングする
+2. `/config` で「Push when actions required」(権限確認などアクションが必要な時)・「Push when Claude decides」(長時間タスク完了時など)を有効にする
+
+- Remote Controlの利用には Pro / Max / Team / Enterprise プランが必要です(Free・個人APIキー利用では使えません)
+- 通知タイミングはClaude(エージェント)自身の判断に委ねられ、確実に発火するとは限りません
+- Apple Watchに専用の設定はありません。iPhoneとペアリングされていれば、iOS側の通知ミラーリングにより自動的に通知が届きます
+- 詳細は [Remote Control のドキュメント](https://code.claude.com/docs/en/remote-control.md) を参照してください
+
 ## 権限方針の要点
```

## 影響範囲の分析

### 動作への影響

`posttooluse-doc-check.sh` は `README*.md` をグロブで拾うが、識別子の削除・変更ではなく追記のみのため、フックの助言対象にはならない。他のフック・スキル・設定への影響はない。

### 後方互換性

既存セクションの内容・見出し・リンクは変更せず、新規セクションの追加のみ。利用者への破壊的影響はない。

### 永続的ドキュメント(`docs/`)への影響

このリポジトリに `docs/` は存在しないため、更新対象なし。今回の唯一の変更対象である `README.md` は、本design.mdの実装アプローチで内容を確定済み。

### 今回の範囲外

- `Notification` フック + 外部プッシュサービス(ntfy.shなど)による自前実装
- `claude.md` の更新
- `todo.md` の該当項目のチェック更新(手順7の後処理で別途行う)
