# todoリストの先頭項目をステアリングとして実行するオプションの追加

## 要点

`.claude/skills/steering-new/SKILL.md` に **`--todo` オプション**を追加する。指定すると、開発タイトルを手入力する代わりに、todo リスト(Markdown のチェックボックス形式)の**先頭にある未完了項目**を開発タイトルとして、既存の手順1〜7(ディレクトリ作成 → overview → requirements → design → docs更新 → tasklist → 実装)をそのまま実行する。ファイル名は省略可能で、省略時はリポジトリルートの `todo.md` を使う。

今の方式で捨てるものはない。既存の `/steering-new [開発タイトル]`(手動でタイトルを指定する呼び出し)はそのまま残し、`--todo` は追加の入力経路として並存させる。新たに増えるのは「開発タイトルの取得元を todo ファイルにできる」という選択肢と、「実装完了後に該当する todo 項目をチェック済みにする」という後処理である。

## 背景

このリポジトリには、着手前のタスクを箇条書きで管理する [`todo.md`](../../todo.md) がある(例: 「ステアリングディレクトリの日付が日本時間とずれている」)。現状、todo に積んだ項目をステアリング作業として着手するには、その都度ユーザーが `todo.md` を見て文面をコピーし、`/steering-new [開発タイトル]` に手で渡す必要がある。

`steering-new` スキル(`.claude/skills/steering-new/SKILL.md`)は、開発タイトルを `$ARGUMENTS` としてユーザー自身が指定する前提で作られている(手順1・「注意事項」参照)。todo からの転記という一手間を、スキル側でファイル名を渡すだけで済ませたい、というのが今回の要求。

## 変更・追加する機能の説明

### 1. `--todo` オプションの追加

`argument-hint` と引数の扱いに `--todo` / `--todo=<ファイル名>` を追加する。

- `--todo`(ファイル名省略): リポジトリルートの `todo.md` を対象にする
- `--todo=<ファイル名>`: 指定したファイルを対象にする(相対パスはリポジトリルート基準)
- 具体的な引数解析の方式(`commit` スキルの `--branch` / `--branch=<名前>` に倣うか等)は design.md で決める

### 2. todoリストからの開発タイトル取得

対象ファイルを Markdown のチェックボックスリストとして読み、`- [ ]` で始まる**最初の未完了項目**をその行のテキストごと開発タイトルとして扱う。以降は既存の手順2(overview.md 作成)以降にそのまま渡す(タイトルの体裁調整のルールも変わらない)。

- 見出し(`## bug` など)による分類は判定に使わない。ファイル先頭からの出現順で最初の `- [ ]` を採用する
- 対象ファイルが存在しない、または `- [ ]` 項目が1件もない場合は、ステアリングを作成せずその旨をユーザーに伝えて終了する

### 3. 実装完了後の todo 項目チェック

手順7(実装)が完了した時点で、開発タイトルの取得元になった todo ファイルの該当行を `- [ ]` から `- [x]` に更新する。todo ファイルの自動編集が許可されない、または対象行が変更されているなど機械的に一致させられない場合は、無理に書き換えずユーザーに手動更新を依頼する。

## 受け入れ条件

- [ ] `/steering-new --todo`(ファイル名省略)で、`todo.md` の先頭の未完了項目を開発タイトルとして手順1〜7が開始される
- [ ] `/steering-new --todo=<ファイル名>` で、指定したファイルの先頭の未完了項目を開発タイトルとして手順1〜7が開始される
- [ ] 対象ファイルが存在しない、または未完了項目が1件もない場合、ステアリングディレクトリを作成せずその旨がユーザーに伝わる
- [ ] 手順7(実装)完了後、対応する todo 項目が `- [x]` に更新される(機械的に対応付けられない場合はユーザーに依頼する旨が明記されている)
- [ ] 既存の `/steering-new [開発タイトル]`(手動指定)の挙動が変更後も変わらない

## 制約事項

- 対象は Markdown のチェックボックス形式(`- [ ]` / `- [x]`)の todo リストに限る。GitHub Issues や外部の課題管理ツールとの連携は対象外
- `todo.md` 自体のフォーマット・運用ルール(見出しの持ち方など)の変更は本タスクの範囲外。既存の `todo.md` をそのまま読める形にする
- 変更対象は `.claude/skills/steering-new/SKILL.md` のみとし、他のスキル(`commit` など)には影響させない
- todo リストの日付・タイムゾーンに関する既知の不具合(`todo.md` に記載のある「ステアリングディレクトリの日付が日本時間とずれている」)は本タスクとは別件であり、今回の対象に含めない
