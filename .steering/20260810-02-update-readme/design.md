# READMEの更新

## 要点

### 採る方式

**README.md(日本語)を「概要 / 含まれるもの / 使い方 / 権限方針の要点 / ステアリング運用」の 5 構成で書き直し、README.en.md に同じ構成の全文訳を作る。** 要約訳ではなく対応する内容を両言語に持たせ、言語切り替えリンクは両ファイルの H1 直下に置く。

| 論点 | 方式 | 決め手 |
|---|---|---|
| 英語版の訳し方 | **全文対訳** | 要約にすると英語話者が受け取れる情報量が日本語版より少なくなる。今回のREADMEは分量が小さく、全文訳のコストも小さい |
| 言語切り替えリンクの位置 | **H1 直下** | 読者が本文を読み始める前に言語を選べるようにする。末尾だと最後まで読んでから気づく |
| README の章立て | 概要 / 含まれるもの(スキル・フック一覧) / 使い方 / 権限方針の要点 / ステアリング運用 | このリポジトリの実体(`.claude/skills/*`・`.claude/hooks/*`・`.claude/settings.json`・`.steering/`)を過不足なく説明できる最小構成 |

### 採らなかった選択肢

- **英語版は要約のみにする** — 日本語版と情報量に差が生まれる。要点に挙げた通り、対等な2言語という requirements.md の方針に反する
- **1 ファイルに両言語を併記する(トグルなし)** — 編集のたびに両言語ブロックが同時に膨らみ、diff で変更箇所が追いにくくなる。ファイルを分けて相互リンクする方が編集・レビューとも単純
- **権限方針・フックの詳細を README に転記する** — `claude.md` の内容と二重管理になり、どちらかを更新し忘れると齟齬が生まれる。README には要点(既定は承認なし・禁止事項だけを列挙、など)のみを書き、詳細は `claude.md` へのリンクに委ねる

## 実装アプローチ

### 1. README.md の書き直し

現行の 1 行説明を、次の構成に置き換える。

1. タイトル・言語切り替えリンク(`🇯🇵 日本語 | [English](README.en.md)`)
2. 概要 — このリポジトリが複数リポジトリで共有する Claude Code 設定(スキル・フック・権限設定など)を管理すること
3. 含まれるもの
   - スキル一覧表: `commit`(コミット規約に従ってコミット)、`steering-new`(ステアリングドキュメントの段階作成)
   - フック一覧表: `pretooluse-block-prohibited.sh`(禁止操作の遮断)、`posttooluse-doc-check.sh`(ドキュメント記述漏れの助言)、`stop-run-tests.sh`(`.claude/test-command` に従ったテスト実行)
4. 使い方 — 利用側リポジトリへ `.claude/` と `claude.md` をコピーして使う運用であること、テストコマンドは `.claude/test-command` に 1 行で置く方式であること
5. 権限方針の要点 — 既定は `bypassPermissions`(承認なし)で、禁止事項だけを `.claude/settings.json` の `deny` とフックで列挙する方針であること。詳細は `claude.md` の該当節を指す
6. ステアリング運用 — 作業単位のドキュメントを `.steering/[YYYYMMDD]-[NN]-[開発タイトル]/` に作ること、詳細は `claude.md` と `.claude/skills/steering-new/SKILL.md` を指す

### 2. README.en.md の新規作成

上記 1〜6 の構成をそのまま英訳する。固有名詞(スキル名・フック名・ファイルパス・コマンド名)は翻訳せず原文のまま使う。

### 3. 言語切り替えリンクの追加

両ファイルの H1 直下に、もう一方の言語版へのリンクを 1 行で置く。

```markdown
# claude-plugins

日本語 | [English](README.en.md)
```

```markdown
# claude-plugins

[日本語](README.md) | English
```

国旗絵文字(🇯🇵 / 🇬🇧)は当初案では言語の目印として使ったが、フォント未対応の環境では絵柄でなく地域インジケータの文字(`JP` / `GB`)として表示されることがあり、意図が伝わらない。プレーンテキストのラベルに置き換える。

### 4. 両言語の同期

README.md の内容を更新する際は README.en.md も同じ変更を反映する運用とし、その旨を両ファイルの末尾に 1 行の注記として残す(例: 「このファイルを更新する際は、対になるもう一方の言語版も合わせて更新してください」)。強制する仕組み(CI・フック)は設けない。既存の `posttooluse-doc-check.sh` は `README*.md` を「参照先ドキュメント」として扱うが、これは他ファイル編集時に削除済み識別子の残存を助言するものであり、README 同士の同期は検知しない。

## 変更するコンポーネント

| ファイル | 変更内容 |
|---|---|
| `README.md` | 全面書き直し。1 行説明を「概要 / 含まれるもの / 使い方 / 権限方針の要点 / ステアリング運用」の構成に置き換え、`README.en.md` へのリンクを追加 |
| `README.en.md`(新規) | `README.md` と対応する構成の英語版を新規作成し、`README.md` へのリンクを追加 |

`.claude/settings.json` / `.claude/hooks/**` / `claude.md` は変更しない。フック側の変更は不要(理由は上記「両言語の同期」参照)。

## データ構造の変更

なし。Markdown ドキュメント 2 ファイルの追加・更新のみで、設定ファイルやスキーマの変更を伴わない。

## 影響範囲の分析

### 動作への影響

- **PostToolUse フック(`posttooluse-doc-check.sh`)**: 対象を `docs/*.md README*.md` のグロブで拾うため、`README.en.md` を追加すると自動的にこのフックの参照先ドキュメントに含まれる。フック自体の変更は不要
- **他のフック・スキル・設定**: README はこれらから参照されないため、動作面の影響はない

### 後方互換性

このリポジトリは README を含めて公開物としての初期整備段階にあり、README の構成を変えることによる利用者側の破壊的変更は生じない(README は API や設定スキーマではなく、外部から機械的に参照されるものではない)。移行手順は不要。

### 永続的ドキュメント(`docs/`)への影響

このリポジトリに `docs/` は存在しないため、更新対象なし。`claude.md` は永続的ドキュメントではなくプロジェクトメモリであり、今回の変更範囲(requirements.md の制約事項)には含めない。

### 今回の範囲外

- `claude.md` の記述更新(現状のままで矛盾はない)
- README 以外のドキュメント(スキル本体の `SKILL.md` など)の見直し
- 言語切り替えを自動化する仕組み(ブラウザ言語判定など。静的な Markdown のため対象外)
